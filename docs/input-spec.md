# N0.1 输入规范与支持矩阵

日期：2026-10-23。状态：**N1 待实现、待验证的输入约定**，不是已支持能力清单。产品规划仍为 v0.2。

基础路径固定为单篇 Markdown＋本地资源 → PDF＋可编辑 LaTeX 源包，模型辅助关闭。只把明确语法映射到结构；普通段落即使写着“定理”也保持正文，不自动分类、补证明或修改数学含义。

## 1. 文档边界

- 入口是一个本地 `.md` 文件，UTF-8，允许 BOM、LF 或 CRLF。工作副本可去 BOM 并统一为 LF；原文件和资源只读。无效 UTF-8 报错，不猜编码。
- 资源根目录默认为入口 Markdown 的父目录。只能引用根目录内直接存在的 PNG/JPEG 文件，不递归合并其他 Markdown。
- 顶部 YAML 仅接受 `title`、`author`、`date`、`lang` 四项，均为普通字符串。`title` 和 `author` 必填且非空，`date` 可省略，提供时使用引号包围的 `YYYY-MM-DD`，不自动补当天日期；`lang` 可省略，默认 `zh-CN`，首版仅接受该值。
- 输入不接受渲染配置、执行配置、模板路径、YAML 自定义标签或别名。未知字段报出名称与位置，不能透传给后端。受控渲染配置在项目侧生成。
- 样例的一级 `#` 是章节，不再重复文档标题；支持 `#`、`##`、`###` 三层 ATX 标题。不跳级，每个章节标题带 `sec-` 标签。数学环境中的标题按环境规则解释。

```yaml
---
title: "一维正交投影为什么最近"
author: "Note2Lecture 示例"
date: "2026-10-23"
lang: "zh-CN"
---
```

## 2. 语法支持矩阵

“支持”表示 N1 必须实现并验收；“诊断”表示拒绝完整成功交付，保留输入并定位。后续适配项要由用户另行安排。

| 内容 | N0.1 约定 | 超出边界时 |
| --- | --- | --- |
| 正文 | 中英文、普通段落、空行；段内源码换行可排为连续文字 | 硬换行、HTML 换行暂不承诺 |
| 文本样式 | `**粗体**`、`*强调*`、反引号行内代码 | 删除线、下划线扩展诊断 |
| 标题与目录 | 三级标题、显式 `sec-` 标签；输出自动目录到第二级 | 更深、跳级、无标签章节诊断 |
| 列表 | 无序 `-`、有序 `1.`，最多两层；列表前有空行 | 任务框、多段复杂列表诊断 |
| 引用段 | 普通 `>`，一层、一个或多个连续文本行 | Obsidian 提示框诊断 |
| 脚注 | `[^id]` 与单段 `[^id]: 内容`，正文首次出现顺序编号 | 缺定义、重复定义、未使用定义诊断；多块脚注暂不支持 |
| 普通链接 | `[说明](https://...)` 或 `http://`，保留可点击链接 | 不抓取链接；本地文档链接、其他协议诊断 |
| 行内数学 | `$...$`，不跨行，内容原样保留 | 不猜测未闭合分隔符；正文美元符写 `\$` |
| 独立数学 | 独占行的 `$$` 起止；结束行可紧接 `{#eq-...}` | `\(...\)`、`\[...\]`、手写 `\label`/`\tag` 暂不接受 |
| 数学命令 | 常用上下标、分式、求和、矩阵、范数和 `aligned` | 自定义宏、宏文件和未知命令定位诊断；支持子集以样例及 N1 编译验证为准 |
| 数学环境 | `def-`、`thm-`、`lem-`、`exm-` 的 fenced div；`.proof` 证明 | 推论、练习、嵌套环境、任意 div 诊断 |
| 交叉引用 | 正文 `@sec-...`、`@eq-...`、`@fig-...`、`@tbl-...` 及四类数学标签 | 允许前向引用；多目标缩写、范围引用和文献引证暂不支持 |
| 代码 | 三反引号围栏；语言可为 `python`、`text` 或省略 | `{python}` 等可执行单元、行内执行、include 指令诊断；任何代码都不执行 |
| 表格 | 单表头管道表格，每格单段文字/行内样式/行内数学，允许列对齐；表后题注与 `tbl-` 标签必填 | 合并单元格、单元格内代码/换行、网格表诊断 |
| 图片 | 独立段的本地 PNG/JPEG，图题非空、`fig-` 标签必填 | SVG、GIF、WebP、PDF、远程图、data URI 暂不接受 |
| Obsidian 扩展 | 首版不适配 `[[双链]]`、`![[嵌入]]`、`> [!note]` | 定位诊断，留 N2 验证，不静默漏掉 |
| 其他输入 | 不接收原始 HTML、数学外原始 LaTeX、短代码、过滤器、文献数据库、多篇拼接 | 定位不支持项，不自行启用其他格式或执行功能 |

代码、行内代码中的 `$`、`@`、`[[...]]` 等是字面内容，不参与数学、引用或扩展语法检查；数学区域也不当作普通正文重新解释。检测应基于解析后的块/内联节点，不能靠全文正则替代。

公式和代码正文除统一换行符外不自动增删字符、改缩进或替换引号。普通文本仅允许确定的格式转换；数学环境标题移入环境题头、标签变为锚点、引用变为编号不算丢字。未经标记的含义更改不属于格式转换。

## 3. 数学环境与显式引用

采用 Quarto 风格的 fenced div，避免另造同义标记。环境以 `:::` 开始、以独立 `:::` 结束。开头只放一个类型标签，块内首个 `##` 为非空环境标题；该标题不进入章节编号或目录。块内支持段落与公式，不允许再嵌套数学环境。

```markdown
::: {#thm-positive-square}

## 实数平方非负

对任意 $x\in\mathbb{R}$，有 $x^2\geq 0$。
:::

::: {.proof}
当 $x\geq 0$ 时结论直接成立；当 $x<0$ 时，$x^2=(-x)^2\geq 0$。
:::

由 @thm-positive-square 可知平方项非负。
```

`def-`、`thm-`、`lem-`、`exm-` 分别显示“定义”“定理”“引理”“例”。证明使用 `.proof`，紧跟所证明的定理或引理，不编号、不接受引用标签；显示“证明”与结束方块。首版不自动把正文的“证明：”变成证明环境。

```markdown
# 误差 {#sec-error}

$$
E=\sum_{i=1}^{n}(x_i-\bar{x})^2.
$$ {#eq-error}

见 @sec-error 和 @eq-error。
```

标签规则：`^(sec|eq|fig|tbl|def|thm|lem|exm)-[a-z0-9]+(?:-[a-z0-9]+)*$`。全篇所有类型合起来唯一，引用大小写敏感，类型和所在结构一致；缺失目标、重复标签或错误前缀均报错。源码中的编号不手写，正文不要额外拼上“定理”等前缀，避免生成“定理定理 1”。电子邮箱等普通 `@` 不是交叉引用。

编号固定为单篇规则：章节 `1`、`1.1`、`1.1.1`；公式、图、表分别从 1 连续编号；定义、定理、引理、例**各自**从 1 连续编号，不随章节重置；证明不编号。只给带标签的独立公式编号，无标签公式不编号；`aligned` 整块一个编号。环境标题不占章节号。N1 必须核对后端计数器并实现此约定，不能直接把后端默认行为当成通过。

引用分别显示“第 1 节”“式 (1)”“图 1”“表 1”“定义 1”“定理 1”“引理 1”“例 1”，可点击到目标。移动已标记对象后重新生成，编号和引用必须一起变化。

## 4. 资源处理

```markdown
![流程说明](assets/mean-flow.png){#fig-flow}

![分批说明](<assets/批次 示意.jpg>){#fig-batches}
```

1. 相对路径以入口 Markdown 所在目录为基准，不以终端工作目录为基准。使用 `/` 分隔；中文路径允许，含空格路径用 `<...>`。N0.1 的源写法不支持手写百分号编码、查询串、片段或反斜杠路径。Pandoc 解析树会把空格规范为 `%20`，适配层须还原解析器生成的编码一次，再进行真实路径检查；保留源路径供诊断，不反复解码。
2. 解析后检查真实路径仍在资源根内；拒绝绝对路径、盘符、UNC、`..` 路径分量及指向根外的链接/联接。不扫描原笔记库，不下载远程资源。
3. 只读取文档直接引用的文件。不把整个 `assets/`、相邻笔记、隐藏文件或源目录递归打包。必须检查文件存在、可读、可解码且真实格式符合 PNG/JPEG 扩展名；扩展名不区分大小写。
4. 源资源字节不改。包内资源命名为 `assets/<完整SHA256>.png` 或 `.jpg`，JPEG 扩展名统一 `.jpg`；按字节摘要去重。改写的是工作副本和 LaTeX 中的路径，并记录原相对路径到新路径的映射。不同目录的同名文件不能覆盖彼此。
5. 图片等比缩放到版心以内，不裁切、不拉伸；限制高度保证单页可容纳图与图题。小图不强行放大；图内文字过小或压缩模糊必须在页面检查中报告。资源文件本身不重采样。
6. 缺图或无法解码属于错误，不用空白占位后声称成功。不能容纳的图表、溢出公式或代码都要定位；禁止静默截断。
7. 输出写到独立目录，不覆盖原 Markdown、资源或已有结果。发现目标已存在时拒绝覆盖，交由用户改用新目录；源包中不能依赖私人绝对路径。

## 5. 诊断约定

诊断至少包含：严重级别、稳定代码、原 Markdown 的相对文件名、1 起始行列、块类型/标签（可用时）、原因和可操作提示。资源错误还要给出原引用路径；重复标签报告两处定义位置。后端编译行号须关联回原输入；无法精确映射时注明近似范围，不能伪称精确定位。

| 代码 | 触发场景 | 期望处理 |
| --- | --- | --- |
| `INPUT_ENCODING` / `INPUT_METADATA` | 编码、元数据或标题层级违规 | 渲染前失败，指出违规项 |
| `UNSUPPORTED_SYNTAX` | 双链、提示框、原始 HTML/LaTeX、未支持命令等 | 指出具体记号及其所在块 |
| `STRUCTURE_INVALID` | 围栏/公式未闭合、环境缺标题或证明位置违规 | 定位起始块和缺失要求 |
| `LABEL_INVALID` / `LABEL_DUPLICATE` | 标签缺失、前缀不符、重复 | 报告标签与定义位置 |
| `REF_UNDEFINED` / `FOOTNOTE_INVALID` | 引用缺目标或脚注不合约定 | 定位引用与相关定义 |
| `RESOURCE_MISSING` / `RESOURCE_INVALID` / `RESOURCE_PATH` | 缺图、格式错误、路径越界或协议不支持 | 不复制其他文件，不继续完整交付 |
| `OUTPUT_EXISTS` / `DEPENDENCY_MISSING` | 输出冲突或缺渲染依赖/字体 | 不覆盖、不自动安装 |
| `COMPILE_FAILED` | XeLaTeX 编译失败 | 保存诊断与日志位置，尽可能映射源块 |
| `LAYOUT_OVERFLOW` / `GLYPH_MISSING` | 裁切、溢出或缺字 | 结果记为失败或待修复，不能完整通过 |

N1 的程序状态为 `complete`、`partial`、`failed`：存在错误时为 `failed`；编译完成但页面待检查或存在未解决版面问题时为 `partial`；程序检查、内容核对和逐页检查通过后才可记为 `complete`。模板审美确认另外记录，不能由程序状态代替。各诊断的具体机器格式和退出码在 N1 实现时落实。

## 6. 规则依据与待验证部分

2026-10-23 对照了官方 [Quarto 交叉引用文档](https://quarto.org/docs/authoring/cross-references.html) 的 div、标签和引用形式，以及 [Markdown 基础文档](https://quarto.org/docs/authoring/markdown-basics.html) 的正文写法。本文的支持边界、编号、中文引用文本、资源政策和诊断是本项目约定，仍需 N1 最小链路验证。

尚未锁定 Quarto、Pandoc、TeX 或字体版本；N0 的语法检查不证明最终中文引用、计数器和分页行为已经实现。N1 如发现约定与后端存在真实冲突，先给出证据和最小调整方案，不静默改变输入协议。
